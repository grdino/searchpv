# Project Atlas
Atlas should make exploring Puerto Vallarta feel as enjoyable as visiting it. Trust Before Persuasion
## Design Principles

---

## Purpose

Atlas is not defined by its features.

It is defined by the experience it creates.

These principles guide every design and development decision.

Whenever multiple solutions are possible, choose the one that best reflects these principles.

---

# 1. Geography Before Real Estate

People discover places before they discover properties.

Atlas always begins with geography.

Properties are an outcome of exploration, not the starting point.

---

# 2. Beauty Before Complexity

If two solutions provide similar functionality, choose the simpler and more beautiful experience.

Atlas should feel calm.

Never overwhelming.

---

# 3. Mobile First

Atlas is designed for the device most people will use.

Every interaction should feel natural on a phone.

Desktop is an enhancement.

Not the primary design target.

---

# 4. Motion Has Meaning

Animations exist to explain.

Not to decorate.

Every movement should help users understand:

• where they are
• what changed
• where they are going

Nothing should move simply because it can.

---

# 5. The Map Is the Canvas

The map is always present.

The workspace changes.

The user should never feel disconnected from geography.

Atlas should rarely navigate away from the map.

---

# 6. Every Place Has One Identity

Every place resolves to one canonical geographic entity.

Aliases exist for people.

Canonical entities exist for software.

Everything connects through that identity.

---

# 7. Progressive Disclosure

Do not show everything at once.

Reveal information as curiosity grows.

A first-time visitor should never feel overwhelmed.

Atlas should reward exploration.

---

# 8. Layers, Not Pages

Atlas is built from independent layers.

Map.

Overlay.

Workspace.

State.

Services.

Each layer has one responsibility.

---

# 9. Context Is Never Lost

The user should always know:

• where they are
• what they are exploring
• how to continue

Changing views should never feel like starting over.

---

# 10. Every Feature Must Earn Its Place

Before adding a feature, ask:

Does it help people understand a place?

Does it simplify the experience?

Does it belong naturally within Atlas?

If not, reconsider.

---

# 11. Data Should Feel Alive

Atlas should not present tables.

It should tell stories.

Market trends.

Neighborhood character.

Nearby discoveries.

The map should invite exploration rather than simply display information.

---

# 12. Grow Without Rebuilding

Atlas will evolve for years.

New capabilities should extend the architecture.

They should not replace it.

The platform should become richer without becoming more complicated.

---

## The Atlas Test

Every design decision should pass one simple test.

"If this were the user's first visit to Puerto Vallarta, would Atlas make them want to keep exploring?"

If the answer is yes...

we are building the right thing.

# One More Thing:

Every screen should answer one question better than any competing product.

For example:

Community View → "What is this place like?"
Market View → "What is happening here?"
Listings View → "What can I buy here?"
Nearby View → "What is around me?"
Compare View → "Which place fits me better?"

If a screen tries to answer five questions at once, it will become cluttered.

If it answers one question exceptionally well, users will naturally move to the next view.
